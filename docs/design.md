# 论文写作模式（Paper Mode）· 设计方案与实现

> 一个装在 DeepSeek Harness Web GUI 里的 Overleaf 式 LaTeX 工作台：
> **源码｜英文排版｜中文排版｜写作助手** 四栏并列，边写边看，边看边问。
>
> 仓库：`paper-mode/` 是插件包本体（bundle `@local/dsh-paper-mode`），`examples/demo-paper/` 是可直接打开的示例论文。
> 入口：左侧栏「论文写作」图标 → 中间栏打开工作台

---

## 1. 一句话定位

Overleaf 给你「源码 + 一份英文排版」；这个模式在你的同一屏里再并排给你两样东西：

1. **同一篇论文的中文排版稿**（不是机翻文本框，是真正用 XeLaTeX 排出来的第二份 PDF，公式、图表编号、参考文献编号与英文版完全一致）；
2. **懂这篇论文的写作助手**（能看到当前文件全文和你选中的那一段，可以直接把润色结果写回编辑器）。

---

## 2. 关键取舍：双语到底「翻译哪一层」

这是整个设计里唯一真正需要想清楚的决定。三条路：

| 方案 | 做法 | 结果 | 结论 |
|---|---|---|---|
| A. 翻 PDF 文本流 | 抽取 PDF 文字 → 机翻 → 重新排版 | 版式全丢，公式变乱码，图表编号散架 | ✗ |
| B. 豆腐块对照 | 右侧放中文译文列表，按段落滚动对齐 | 只有文字，没有「排版结果」，断行/公式/浮动体全无 | ✗ |
| C. **翻源码再编译** | 保留 LaTeX 结构，只把自然语言换成中文，用 XeLaTeX 重新排版 | 得到**第二份真正排版好的中文 PDF**，与英文版同构 | ✓ 采用 |

方案 C 的关键难点只有一个：**怎么在翻译时保住 LaTeX 结构**。

做法是「占位符保护」：

```
源:  Let $x \in \mathbb{R}^n$ be the input, as shown in~\cite{smith2020}.
送模型:  Let <<4>> be the input, as shown in~<<7>>.
模型返回:  设 <<4>> 为输入，如 <<7>> 所示。
回填:  设 $x \in \mathbb{R}^n$ 为输入，如~\cite{smith2020} 所示。
```

- 公式、`\cite`、`\ref`、`\label`、`\url`、`\includegraphics`、`\\` 换行、`\%` 这类转义 → 全部变成 `<<n>>` 占位符，模型不能翻译、不能改；
- `\textbf{...}`、`\emph{...}` 这类**只包文字**的命令保留成 LaTeX 原样交给模型，让它把命令里的词翻掉（`\textbf{scales}` → `\textbf{扩展}`），这样句子上下文完整；
- 环境级的**代码块**（`equation`、`align`、`tabular`、`verbatim`、`lstlisting`）整段原样跳过，一个字都不送模型；
- `%` 注释不进译文，原样保留在源码里。

于是中文稿的 95% 排版问题（公式断裂、引用丢失、浮动体错位）在源头就消失了。

## 3. 界面

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 📄 demo-paper  ~/papers/demo-paper  [打开][新建][编译] [源码][中文][助手]  状态  │
├────────────┬──────────────┬──────────────┬───────────────────────────────────┤
│ 源文件 tabs │ English      │ 中文对照      │ 写作助手                           │
│ ─────────  │ ───────────  │ ───────────  │ ────────────────────────────────  │
│ 1 \document│ ┌──────────┐ │ ┌──────────┐ │  (对话气泡 / 流式输出)             │
│ 2 \usepack │ │ PDF 第 1 页│ │ │ PDF 第 1 页│ │                                   │
│ 3 ...      │ └──────────┘ │ └──────────┘ │ ────────────────────────────────  │
│            │ ┌──────────┐ │ ┌──────────┐ │ [润色][压缩][审稿][译成中文]        │
│ 行号 +     │ │ PDF 第 2 页│ │ │ PDF 第 2 页│ │ ┌───────────────────────────┐     │
│ 等宽编辑器 │ └──────────┘ │ └──────────┘ │ │ 输入…              [发送]  │     │
│            │              │ ⇅ 同步滚动    │ └───────────────────────────┘     │
└────────────┴──────────────┴──────────────┴───────────────────────────────────┘
```

**顶栏**：项目 chip（名称 + 路径）｜编译（Ctrl+Enter）｜自动编译开关｜打开 / 新建｜视图三键（源码 / 中文 / 助手）｜阶段提示。

**底栏**：当前阶段或"就绪"｜EN / 中文 页数与耗时｜错误 / 警告徽标｜日志开关。除了顶栏的阶段提示，每一次动作还会弹出 toast（成功 3 秒、失败 6 秒）。

**编译设置面板**（顶栏右侧 ⚙，像 Overleaf 的 Compile settings）：

| 分组 | 选项 | 作用 |
|---|---|---|
| 编译 | 编译器 | XeLaTeX / pdfLaTeX / LuaLaTeX |
| | 主文件 | 多文件工程里指定根文档 |
| | 页面清晰度 | 96 / 110 / 144 / 200 dpi（越高越清晰，图片也越大） |
| | 快速模式（只跑一遍） | 跳过交叉引用刷新，最快；编号可能暂时是 `??` |
| | 出错即停 | 默认关：即使有错也输出能排出来的部分 |
| | 参考文献 | 自动 BibTeX（引用集或 .bib 变了才重跑）/ 不处理 |
| 中文对照 | 生成中文版本 | 临时关掉中文这条流水线 |
| | 中文宏包 | xeCJK / ctex / 不注入（文档自带时用） |
| 自动编译 | 停笔即编译 | 开关 |
| | 延迟 | 0.8s / 1.4s / 3s |

设置存在浏览器本地，改「编译器 / 宏包 / dpi / 快速模式 / 主文件」会立刻重编一次。

**源码 ↔ 排版双向定位**：双击 PDF 里任意位置，编辑器立刻跳到对应源码行；反过来，光标在源码里移动时，英文页会自动滚到对应位置并闪一下高亮框。用的是真正的 SyncTeX（`xelatex -synctex=1`），不是按页猜的。实测编译开销约 0.05 秒。

**PDF 可选中**：每页位图上面盖了一层透明的文字层。文字层来自 `pdftotext -bbox-layout` 逐行的矩形，按页面尺寸等比缩放，再用 `scaleX` 把不可见字形拉伸到与印刷文字同宽——所以拖选、双击选词、`Ctrl+C` 都和在真 PDF 阅读器里一样。选中内容会作为上下文一起发给助手（输入框上方有提示条，可一键清除）。

**每栏都有明确的空态与忙碌态**：中文栏第一次编译要十几秒，期间显示转圈和「第一次编译会逐段翻译并重新排版」的说明，而不是一片空白。

其他交互决定：

- 三条竖分隔条可拖动改宽度；宽度、缩放、同步滚动、三栏显隐全部记在 `localStorage`，下次打开还是你的布局；
- PDF 用**逐页位图**渲染而不是 `<iframe>`：这样才能做到中英两栏按页对齐、滚动镜像、缩放联动；
- 编译错误列在底部抽屉里，**点一条就跳到源码对应行并选中**；
- 聊天区空态给三张「建议卡」（审稿 / 压缩 / 地道化），有选区时自动把选区带上；消息带角色标签、复制按钮，代码块带「替换选中 / 追加到末尾」；
- 助手栏可整体收起，只看双栏排版时能腾出宽度。

### 3.1 不允许"静默失败"

第一版点「编译」没反应，根因是**内容没变就提前 return**：打开项目后自动编译过一次，再点按钮时指纹一致，函数直接返回，界面上什么也没发生。

现在的规则：

1. 手动点「编译」= `force`，一定重新发请求，不看指纹；
2. 排版进行中再点，不是禁用按钮，而是**排队**并提示「已排队，本轮结束后自动开始」；
3. 任何失败都会同时写到顶栏、底栏和 toast 三处，不可能只闪一下；
4. 找不到主文件、没打开项目这类前置条件也会明确报出来，不再无声返回。

## 4. 架构

一个 bundle，双面插件（Host 半 + 浏览器半）：

```
paper-mode/
├─ package.json          dsh.bundle.patch + dsh.client（platform: web）
├─ cordis.patch.yml      一行插件注册（inject: webServer）
├─ index.js              Host 半：HTTP 路由 / 编译 / 翻译编排 / SSE 对话
├─ lib/tex.js            LaTeX 分段器：保护、切分、CJK 导言区注入
├─ lib/translate.js      分批翻译、JSON 解析、结构校验、缓存、重试降级
├─ client.js             浏览器半：四栏工作台（React.createElement，无构建）
├─ locale/{zh,en}.json   插件在插件市场/设置里的名称与描述
└─ icon.svg
```

| 层 | 职责 |
|---|---|
| 浏览器半 | 只做界面与交互：编辑器、翻页阅读、聊天流、布局。通过 `api/dsh-paper/*`（文档相对路径）调 Host |
| Host 半 | 所有重活：目录发现、文件读写、复制构建树、调 `xelatex`/`bibtex`/`pdftoppm`、调 `ctx.llm` 翻译与对话、静态资源服务 |
| 插槽 | `sidebar.panellist` 注册面板图标（`id = paper-mode`），`main` 注册同 key 的页面；壳层负责选中、高亮、收起态 |

选这两个插槽是刻意的：走壳层自己的面板机制，侧栏行、图标尺寸、激活态、折叠态、切换动画全部由壳层负责，插件不碰别人的 DOM。

## 5. 数据流

### 5.1 编译（两条请求并行，英文抢跑 550ms）

```
编辑器按键
   └─ 防抖（默认 1.4s）──┬─► POST /build {mode:"en", options}
                          │     ├ 增量同步工程 → <tmp>/dsh-paper/<hash>/en
                          │     ├ 覆盖脏缓冲区
                          │     ├ xelatex ×1（需要时补第 2/3 遍 / bibtex）
                          │     ├ pdfinfo → pdftoppm（同内容复用旧页面）
                          │     └ 返回 {rev, pages, passes, errors[]} ──► 英文栏出图
                          └─► +550ms：POST /build {mode:"zh", options}
                                ├ 增量同步工程（.tex 由翻译产出，不从源镜像）
                                ├ 逐文件翻译（见 §6），只读项目、只写构建树
                                ├ 注入中文导言区
                                ├ xelatex ×1（失败则换下一套导言区重试）
                                └ 返回 {rev, pages, stats} ──► 中文栏出图
```

**为什么拆两条请求**：英文约 2 秒、中文首次要调模型。合成一条会让用户盯着空白等十几秒。拆开后英文先落屏；两条请求在 Host 上按 `(项目, 面)` 分别排队，互不阻塞，中文那条的翻译阶段（网络 IO）与英文的编译重叠。

**为什么还要错开 550ms**：两条 `xelatex` 同时跑会在 MiKTeX 的字体库锁上互相等，实测英文会慢 0.5 秒。错开后英文拿到 CPU 先完成，中文的翻译照样从 0 秒开始跑。

### 5.2 三层缓存

| 层 | 存哪 | 键 | 命中时 |
|---|---|---|---|
| 构建结果 | 宿主内存 | 编译选项 + 主文件 + 全部源文件的 size/mtime + 脏缓冲区内容 + 模式 | **0 ms** 直接返回上次的页图与 PDF，连 LaTeX 都不启动 |
| 翻译记忆 | `$DSH_HOME/paper-mode/translation-cache.json` | `sha256(提示词版本 + 模型 + 占位符化段落)` | 该段不发模型请求；跨项目、跨重启复用 |
| 页图 | 临时目录 `pages/<内容哈希>@<dpi>/` | PDF 内容哈希 + dpi | 不再调用 pdftoppm |

翻译记忆放在 Harness home 而不是项目目录或临时目录：这样重启、换项目都还在，「同一段话在第二篇论文里免费」。旧版按项目存的缓存会在首次使用时自动迁移过来；文件超过 3 万条时裁掉最旧的三分之一；两个项目同时写入时会先读盘再合并，不会互相覆盖。

每次排版结束会把消耗报给前端：`已译 N 段 / 复用 M 段 / X tokens（缓存命中 Y）`，能直接看到省了多少。

### 5.3 增量与短路（这是快的主要原因）

| 手段 | 省掉什么 |
|---|---|
| 构建树增量同步（按 size+mtime 只拷改过的） | 每次重拷整个工程 |
| 保留 `.aux/.bbl/.toc`，只在日志要求 `Rerun` 时补第二遍 | 稳定文档从 2 遍降到 1 遍 |
| 参考文献指纹（引用集 + .bib 的 size/mtime） | 没改文献就不跑 BibTeX |
| PDF 内容哈希相同 → 复用已栅格化的页图 | 重编未改动文档时零栅格化 |
| 翻译缓存（段落哈希） | 只翻改过的段落 |
| 翻译批次 3 路并发 | 批次 latency 串行相加 |
| 翻译显式用模型支持的最低推理档（实测 `off`） | 默认可能是最高推理档，纯机械翻译白等几十秒 |

### 5.4 构建产物不进仓库

所有中间产物在系统临时目录：`<tmp>/dsh-paper/<工程路径 sha1 前 12 位>/`。
构建树、逐页 PNG、翻译缓存都在那里，**论文仓库里一个文件都不会多出来**（这一点和 Overleaf 本地版、latexmk 默认行为不同，是刻意的）。

### 5.5 双向定位（SyncTeX）

编译时带上 `-synctex=1`，产出 `.synctex.gz` 侧车文件；两个方向都走宿主进程里的 `synctex` 命令：

| 方向 | 命令 | 触发 |
|---|---|---|
| PDF → 源码 | `synctex edit -o <页>:<x>:<y>:<pdf>` | 双击文字层，把点击位置换算成 PDF 点（同一套缩放比例） |
| 源码 → PDF | `synctex view -i <行>:<列>:<绝对路径>` | 编辑器光标移动（260 ms 防抖），滚动并闪烁高亮框 |

几个必须处理的细节：

- **路径必须绝对**：`synctex view -i` 只认编译时记录的绝对路径，用相对路径会报 `No tag`；
- **生成内容没有源码行**：点参考文献会落到 `main.bbl`，这里回退到主文件里 `\bibliography{...}` 那一行（目录、图表索引同理）；
- **中文版偏移**：中文稿在 `\documentclass` 后插了一段导言区，行号整体下移；反向定位时按注入行数减回去，所以点中文版标题和点英文版标题给的是同一行；
- **防抖与防回环**：从 PDF 跳回源码时会压制 700 ms 的「跟随」，否则编辑器选区变化又会把 PDF 滚回去。

### 5.6 页面级复用

- 逐页 PNG 按 PDF 内容哈希 `rev` 命名，前端 `<img src="...rev=...">` 直接吃浏览器缓存；
- 翻译缓存键 = `sha256(model + 占位符化后的段落)`，段落没改就不重新请求；
- 逐页 PNG 目录键是 `<内容哈希>@<dpi>`，所以只改清晰度不会串图。

## 6. 翻译管线（`lib/tex.js` + `lib/translate.js`）

### 6.1 分段

一个字符级扫描器，按「块级边界」把源码切成三类片段：

| 片段 | 例子 | 处理 |
|---|---|---|
| `keep` | 导言区命令、环境外壳、注释、公式环境、表格体 | 原样拼接 |
| `tr` | 正文段落、`\section{}`、`\caption{}`、`\title{}`、`\item` 后的文字 | 送翻译 |
| 原子 token | `$..$`、`\cite{}`、`\ref{}`、`\label{}`、`\includegraphics`、`\\`、`\%` | 变 `<<n>>` |

往返性质是做单测验证的：`rebuild(parse(src), {}) === src`，逐字节相同。

### 6.2 校验

模型返回后，对本段做三件事的**多重集比对**：

1. `<<n>>` 占位符数量与编号；
2. `\command` 出现次数；
3. 花括号平衡。

任一项不符 → 整批重试一次（提示词里点明"占比符不一致"）→ 仍不符则**逐段单独重试** → 仍失败就保留英文原文并在 `stats.problems` 里记录原因。

这一步是整个方案的安全带：宁可某段没翻，也绝不让 `\cite` 丢掉或花括号错位把中文稿编译崩掉。

### 6.3 分批

每批 ≤ 6 段 / ≤ 1200 字符。更大的批次会显著抬高 JSON 截断和占位符漂移的概率（第一版用 14 段/2800 字，首次构建 16 段里 14 段校验失败；改为 6 段/1200 字后 16 段全过）。

### 6.4 中文导言区（三级回退）

主文件 `\documentclass` 之后注入，按顺序尝试，编译成功就停：

注入的块用 `% >>> paper-mode: generated CJK preamble >>>` 与 `% <<< ... <<<` 包起来，这样换变体时能原地替换，也方便读者看出哪些行是工具加的。

1. `xeCJK` + **按平台选字体**（Windows: SimSun/SimHei/FangSong；macOS: Songti SC/Heiti SC/STFangsong；Linux: Noto Serif/Sans/Mono CJK SC）+ `\XeTeXlinebreaklocale "zh"` + 一节标题名重定义（`摘要`/`参考文献`/`图`/`表`/`目录`）+ 中文 `\today`；
2. `ctex`（`heading=false`，`fontset=fandol`，Fandol 是 TeX 自带字体，没有系统中文字体的机器也能排）；
3. `ctex`（`fontset=windows`）。

行号偏移不靠数块的行数，而是拿生成文件和原文的行数差直接算，换变体后重新算一遍——SyncTeX 的反向定位依赖这个偏移。

若原文档本来就用 `ctexart` / `xeCJK`，跳过注入。

### 6.5 术语与文体

系统提示词固定了几条硬约束：学术书面语；术语首次出现写「中文（English）」、其后只写中文；数字/单位/变量/人名/机构名保持原样；不加译者注、不增删内容。

## 7. 写作助手

- 走 Host 的 `ctx.llm`，默认用 `agentDefaultModel` 里的当前默认模型（可用环境变量 `PAPER_MODE_MODEL=provider/model` 覆盖）；
- 每次请求自动携带：项目路径、主文件、当前文件、**选中片段**、当前文件全文（截断 24k 字符）；
- SSE 流式输出，前端逐字追加，可「停止」；
- 回复里的 ```latex 代码块带两个按钮：**替换选中** / **追加到末尾**，点一下直接改编辑器缓冲区，1.4 秒后自动保存并重编 → 中文栏随之更新；
- 四个快捷动作（润色 / 压缩 / 审稿 / 译成中文）作用于当前选区。

系统提示词里明确禁止编造数据、实验结果和 bibtex 条目——这是论文场景下最容易出问题的地方。

## 8. 安装与使用

已在当前 profile 装好（`@local/dsh-paper-mode`，link 安装，改代码后重启宿主生效）。

1. 刷新 GUI 页面（F5）；
2. 左侧栏点「论文写作」；
3. 点「打开文件夹」，选一个含 `main.tex` 的目录；或点「新建项目」从模板生成；
4. 开始写。停笔 1.4 秒自动保存 + 重编彩色双栏。

环境要求：本机需有 `xelatex`、`bibtex`、`pdftoppm`、`pdfinfo`（MiKTeX 或 TeX Live 都带）。打开项目时会返回 `toolchain` 探测结果。

## 9. 已验证

- LaTeX 分段往返：字节级一致（`paper-mode/test/tex.test.mjs`）；
- 无模型桩跑通全链路：copy → 编译 → 栅格化 → 资源路由（`paper-mode/test/`）；
- 真实模型：`examples/demo-paper` 的 2 页论文 16 段全部译出、0 段失败、中文 PDF 2 页编译通过；
- 性能（2 页示例论文，同一台机器，服务端计时）：冷启动双语 7.6s（原先 21s+），热重编 **EN 1.7~2.1s / ZH 2.1~2.7s，两条并行 3.8~4.2s**（原先 5.4s + 7.1s）；改一段文字后重编约 4.5s；
- 缓存：内容未改时再点编译 **0 ms**（构建签名命中）；改一段后只译该段（实测 15 段命中、1 段新译、1 次模型调用 376 in / 153 out tokens）；
- PDF 文字层：`pdftotext -bbox-layout` 解析出的行框与页图对齐，示例 2 页共 46 行/页；
- 双向定位：英文页点标题→第 15 行、点摘要→第 17 行、点参考文献→`\bibliography` 所在第 62 行；中文页点标题同样回到第 15 行（导言区偏移已扣除）；反向前向同步第 20 行→第 1 页 y≈312 的方框；
- 公式、`\ref`/`\cite` 编号、表格、参考文献在中文版中位置与英文版一致；
- 未保存缓冲区直接编译（`files` 覆盖）生效，不依赖先落盘；
- 插槽注册：`main` 槽 `paper-mode` 占用者 `active: true`；
- **浏览器半的真实挂载测试**（`paper-mode/test/mount.test.mjs`，jsdom + React 18 + 假 Host）：11 项全过，覆盖空态→自动打开上次项目→自动编译→双栏出图→**内容未变时点编译仍发请求**→打字自动保存并重编→助手栏收起/恢复→日志抽屉打开。

## 10. 已知限制

| 限制 | 说明 / 下一步 |
|---|---|
| 表格内容不翻译 | `tabular` / `longtable` 整段保留原文（数字为主，翻译收益低、风险高）。下一步：按单元格切分，只翻纯文字单元格 |
| 中文版页数与英文版可能不同 | 中文更紧凑，2 页英文常压到 1.5 页；逐页对照是"第 1 页对第 1 页"，不是逐行对齐 |
| 图注可翻、图内文字不翻 | 图是位图，需 OCR，不在本版范围 |
| 首次中文构建 15~25 秒 | 受模型与两次 XeLaTeX 限制；缓存后 7 秒左右 |
| 路由未做宿主鉴权 | 仅监听本机、且加了 Origin 同源校验（拒非 localhost Origin）。多用户/远程部署前应接上 harness 的浏览器鉴权 cookie |
| 单文件编辑 | 编辑器是纯 textarea（行号 + Tab + Ctrl+S），没有语法高亮和自动补全 |
| 助手无工具循环 | 只能读当前文件上下文，不能自己 grep 全仓库或跑 bib 检查。下一步：给 Host 半加 read/write/search 工具循环 |

## 11. 下一步优先级

1. **表格单元格翻译**（收益最大）；
2. **助手工具循环**（让它能自己读相关章节、改文件、查引用）；
3. **源→PDF 正向定位**（点 PDF 跳源码，靠 SyncTeX，`-synctex=1` 已就位）；
4. 编辑器升级 CodeMirror 6（语法高亮、多光标、折叠）；
5. 多文件工程的 `\input` 依赖图，只为主文档可达的文件付费翻译。
